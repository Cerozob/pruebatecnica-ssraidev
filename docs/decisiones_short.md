# Decisiones Técnicas (Resumen)

* Autor: **Camilo Rozo**

Resumen de las decisiones de arquitectura. El detalle de cada una (contexto, consecuencias y cumplimiento) está en [decisiones_full.md](decisiones_full.md).

| ID | Nombre | Descripción | Razón |
|---|---|---|---|
| [ADR-001](decisiones_full.md#adr-001-aws-como-plataforma) | Plataforma cloud | AWS | Es la nube donde tengo mayor experiencia; ejecutar localmente igual exigiría documentar un despliegue en la nube. |
| [ADR-002](decisiones_full.md#adr-002-cómputo-serverless-con-escalado-a-cero) | Modelo de cómputo | Serverless con escalado a cero; Fargate solo para la evaluación | Costo por uso a baja escala; la evaluación puede superar el límite de 15 minutos de Lambda. |
| [ADR-003](decisiones_full.md#adr-003-api-con-lambdas-de-powertools-detrás-de-api-gateway) | Implementación de la API | Lambdas de Powertools detrás de API Gateway | ECS con ALB es más costoso a esta escala; los handlers se pueden reutilizar. |
| [ADR-004](decisiones_full.md#adr-004-región-us-east-1) | Región | `us-east-1` | Menor latencia desde mi ubicación y todos los servicios disponibles. |
| [ADR-005](decisiones_full.md#adr-005-frontend-web-en-react) | Frontend | React servido desde S3 y CloudFront | Facilita la demostración; es mi framework preferido y HTML sin framework es difícil de mantener. |
| [ADR-006](decisiones_full.md#adr-006-inicio-de-sesión-administrado-de-cognito) | Inicio de sesión | *Managed login* de Cognito | Simple, fácil de implementar y se ve bien. |
| [ADR-007](decisiones_full.md#adr-007-registro-restringido-con-un-lambda-pre-signup) | Restricción del registro | Lambda *Pre SignUp* con lista de correos y dominios permitidos | Evitar registros no deseados. |
| [ADR-008](decisiones_full.md#adr-008-api-rest-de-api-gateway-en-lugar-de-http-api) | Tipo de API | API REST de API Gateway | Más funcionalidades: *authorizer* de Cognito y limitación de tasa. |
| [ADR-009](decisiones_full.md#adr-009-carga-de-documentos-directa-a-s3-con-urls-prefirmadas) | Carga de documentos | Directa a S3 con URLs prefirmadas, sin multiparte | Documentos de hasta 50 MB, el límite de la base de conocimiento; sin multiparte por simplicidad. |
| [ADR-010](decisiones_full.md#adr-010-sincronización-de-la-base-de-conocimiento-por-eventos) | Sincronización de la base de conocimiento | Incremental por eventos con EventBridge, con sincronización manual de respaldo | Los usuarios esperan que los documentos estén disponibles de inmediato. |
| [ADR-011](decisiones_full.md#adr-011-base-de-conocimiento-administrada-de-bedrock-con-configuración-por-defecto) | Base de conocimiento | Bedrock Knowledge Base administrada con configuración por defecto | Menor costo y operación; multimodal, con *parsing* y *embeddings* sin costo adicional. |
| [ADR-012](decisiones_full.md#adr-012-strands-agents-como-framework-de-agentes) | Framework de agentes | Strands Agents | Preferencia y experiencia previa. |
| [ADR-013](decisiones_full.md#adr-013-patrón-swarm-para-la-colaboración-entre-agentes) | Colaboración entre agentes | Patrón *swarm* | Probar un patrón nuevo; un grafo no sirve para consultas tan diversas. |
| [ADR-014](decisiones_full.md#adr-014-tres-agentes-conversacional-de-modernización-y-recomendador-de-servicios-cloud) | Número de agentes | Tres: conversacional, de modernización y recomendador de servicios cloud | Modernización y recomendación no están alineadas con el requerimiento principal. |
| [ADR-015](decisiones_full.md#adr-015-amazon-bedrock-agentcore-runtime-para-ejecutar-los-agentes) | Ejecución de los agentes | AgentCore Runtime | Optimizado para agentes y no cobra el cómputo inactivo. |
| [ADR-016](decisiones_full.md#adr-016-amazon-nova-2-lite-como-modelo-de-lenguaje) | Modelo | Amazon Nova 2 Lite (provisional) con el perfil de inferencia global | Costo: es por mucho el modelo más barato; se acepta menor calidad que Claude Sonnet 4.5. Perfil global, luego `us.`, luego el ID del modelo. |
| [ADR-017](decisiones_full.md#adr-017-contexto-de-la-conversación-en-agentcore-e-historial-en-dynamodb) | Contexto e historial de conversación | Contexto en AgentCore Runtime y AgentCore Memory por sessionId; historial del usuario en DynamoDB | El servicio administra el contexto sin un Lambda de larga duración; el frontend consulta el historial. |
| [ADR-018](decisiones_full.md#adr-018-respuestas-síncronas) | Modo de respuesta | Síncrono; si supera los 29 s de API Gateway, el turno se guarda igual | Simplicidad. |
| [ADR-019](decisiones_full.md#adr-019-herramientas-expuestas-por-agentcore-gateway-mcp) | Exposición de herramientas | AgentCore Gateway (MCP) | Observabilidad de las herramientas y reutilización en otros agentes, incluso fuera de AWS. |
| [ADR-020](decisiones_full.md#adr-020-herramientas-de-solicitudes-implementadas-en-lambda) | Herramientas de solicitudes | Lambda | Costo, despliegue sencillo y control total. |
| [ADR-021](decisiones_full.md#adr-021-sin-operación-de-eliminación-de-solicitudes) | Eliminación de solicitudes | No existe, ni en IAM ni como herramienta | Seguridad ante acciones destructivas. |
| [ADR-022](decisiones_full.md#adr-022-prioridad-y-esfuerzo-los-decide-el-llm-con-niveles-fijos) | Prioridad y esfuerzo | Los decide el LLM con niveles `low`, `medium` y `high`; por defecto `unassigned` | Simplicidad. |
| [ADR-023](decisiones_full.md#adr-023-búsqueda-web-restringida-a-documentación-de-aws-y-azure-solo-para-agentes-especializados) | Búsqueda web | Herramienta de AgentCore restringida a documentación de AWS y Azure, solo para agentes especializados | El agente principal responde solo desde la base de conocimiento. |
| [ADR-024](decisiones_full.md#adr-024-dynamodb-para-solicitudes-y-evaluaciones) | Almacenamiento de solicitudes y evaluaciones | DynamoDB | Base de datos real con esquema flexible y aprovisionamiento mínimo; Aurora es más costosa. |
| [ADR-025](decisiones_full.md#adr-025-datos-de-ejemplo-con-bucketdeployment-y-un-custom-resource) | Datos de ejemplo | `BucketDeployment` para documentos y *custom resource* para 10 solicitudes ficticias en JSON | Solución lista tras el despliegue; el frontend accede a las solicitudes solo a través del agente. |
| [ADR-026](decisiones_full.md#adr-026-bedrock-guardrails-solo-para-detectar-prompt-injection) | Protección contra *prompt injection* | Bedrock Guardrails solo con ese filtro; el usuario ve que fue bloqueado | Servicio administrado y simple; más filtros aumentan el costo. |
| [ADR-027](decisiones_full.md#adr-027-secrets-manager-para-los-correos-y-dominios-permitidos) | Correos y dominios permitidos | Secrets Manager | Es el almacén estándar de credenciales; SSM `SecureString` sería una buena alternativa. |
| [ADR-028](decisiones_full.md#adr-028-roles-iam-de-mínimo-privilegio-con-comodines-solo-cuando-son-inevitables) | Permisos IAM | Mínimo privilegio, un rol por recurso | Comodines solo para lecturas de S3 de la base de conocimiento y permisos obligatorios. |
| [ADR-029](decisiones_full.md#adr-029-respuestas-fundamentadas-con-referencias-obligatorias-y-conversaciones-privadas-por-usuario) | Fundamentación y aislamiento | Referencias obligatorias, "no tengo esa información" y conversaciones privadas por usuario | Respuestas verificables; documentos y solicitudes compartidos por simplicidad. |
| [ADR-030](decisiones_full.md#adr-030-evaluación-agéntica-con-strands-evals-y-agentcore-evaluations) | Framework de evaluación | Strands Evals y AgentCore Evaluations | Evaluaciones y métricas ya implementadas, sin reimplementarlas. |
| [ADR-031](decisiones_full.md#adr-031-step-functions-para-orquestar-la-evaluación) | Orquestación de la evaluación | Step Functions | Observabilidad, trazabilidad de errores y monitoreo de un flujo determinista. |
| [ADR-032](decisiones_full.md#adr-032-amazon-nova-2-lite-también-como-modelo-juez) | Modelo juez | El mismo modelo de los agentes, Amazon Nova 2 Lite (provisional) | Costo; se acepta el sesgo de autoevaluación como riesgo conocido. |
| [ADR-033](decisiones_full.md#adr-033-pruebas-de-evaluación-por-agente-y-por-tipo-de-riesgo) | Pruebas de evaluación | Precisión y *groundedness* para los tres agentes, información insuficiente para el conversacional y *prompt injection*; un caso aprueba con 0.6 o más | Cubrir las cuatro evaluaciones que pide la prueba y los tres agentes, verificando las fuentes. |
| [ADR-034](decisiones_full.md#adr-034-aws-cdk-en-python-con-cdk-nag) | Infraestructura como código | AWS CDK en Python con cdk-nag | Preferencia y experiencia; cdk-nag valida buenas prácticas antes de desplegar. |
| [ADR-035](decisiones_full.md#adr-035-varios-stacks-separados-por-dominio) | Organización de los stacks | Varios stacks separados por dominio | Los componentes de un mismo dominio tienen ciclos de vida similares. |
| [ADR-036](decisiones_full.md#adr-036-ssm-parameter-store-para-la-configuración-de-runtime) | Configuración de runtime | SSM Parameter Store | Cambios en tiempo de ejecución sin tiempo de inactividad. |
| [ADR-037](decisiones_full.md#adr-037-visor-de-logs-en-el-frontend) | Consulta de logs | Visor de logs en el frontend, limitado a los *log groups* con las etiquetas de la aplicación | Los usuarios finales no son técnicos ni tienen acceso a la consola de AWS. |
| [ADR-038](decisiones_full.md#adr-038-registro-de-invocaciones-de-modelos-de-bedrock-activado) | Registro de invocaciones de modelos | Activado, en CloudWatch (3 meses) y en S3 (bucket retenido) | Observabilidad; los registros sobreviven a la eliminación de la solución. |
| [ADR-039](decisiones_full.md#adr-039-capacidades-de-producción-fuera-del-alcance-por-simplicidad-y-costo) | Capacidades de producción | WAF, VPC, varios entornos, CI/CD, *multi-tenant*, dominio propio y observabilidad avanzada fuera del alcance | Simplicidad y costo: corre en mi cuenta personal. |
| [ADR-040](decisiones_full.md#adr-040-cloudscape-como-librería-de-componentes-del-frontend) | Librería de componentes del frontend | Cloudscape Design System | Es la librería de componentes de código abierto oficial de AWS. |
| [ADR-041](decisiones_full.md#adr-041-documentación-de-la-api-con-openapi-desde-api-gateway) | Documentación de la API | OpenAPI gestionado desde API Gateway y documentación de uso generada con IA | La especificación vive con la API, y el comportamiento de cada endpoint es el que indica su nombre. |
| [ADR-042](decisiones_full.md#adr-042-modelo-de-datos-de-las-solicitudes) | Modelo de datos de las solicitudes | `id` (UUIDv7), `description`, `summary`, `priority`, `effort` y `status`, con valores por defecto | El agente completa la solicitud según el flujo de la conversación. |
